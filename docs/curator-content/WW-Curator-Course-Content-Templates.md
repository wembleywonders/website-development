# WW Curator Course Content Templates
*Derived from two built-and-tested examples: Balla Fasséké (Pageturners, craft-based) and Coxsone Dodd (Trubble n Bass, relationship-based). Two templates, not one — the two examples proved a single shape can't cover both technique types.*

---

## HOW TO USE THIS DOCUMENT

Before writing any curator's lesson content, determine which template applies:

**CRAFT-BASED** — the technique produces a personal artifact a learner can make alone (a poem, a beat, a design, a piece of code, a transcription). Use Template A.

**RELATIONSHIP-BASED** — the technique only exists in contact with another person's real, unfinished work (mentorship, A&R, platform-sharing, coaching). Use Template B.

If genuinely unsure which applies: ask "could a learner practice this alone, on paper, with a clean right-or-wrong self-check?" If yes → Template A. If no → Template B.

**The [REAL TOOL] field in both templates is mandatory, not optional.** It must name an actual, verified sandbox component or evidence mechanism — not an assumed or aspirational one. If no real tool exists yet for this curator, STOP and flag it as a build gap before writing further content, the same way Imhotep and Elijah McCoy's Skunkworks gap was found. Do not write a lesson pointing at something that doesn't exist; that recreates the exact "provided ≠ verified" failure this whole project has been catching all session.

Two paths, added 22 Aug 2026 after the Dodd Builder-tier build:

- **Organic path (default).** The member finds a real coaching/mentorship
  situation in their own existing circle and writes it up. This is the
  closest match to how these curators actually worked (Dodd, Kitchener,
  Vaughan all developed people they were already around) — it stays the
  primary path, not a fallback.
- **Structured-pairing path (optional).** A scheduled Zoom session pairing
  two members, with a facilitator present who witnesses the coaching
  attempt directly. Use this when a member has no obvious person to coach
  in their own circle, or when a genuine third-party witness is wanted —
  facilitator sign-off is stronger evidence than a self-reported written
  account, and functions as the human-verification layer
  `DevelopmentEvidence` was designed for but has no UI to collect yet. This
  does NOT solve the deeper craft-vs-relationship gap — a scheduled session
  still requires another real person; it moves *where* the interaction
  happens and *who* can verify it, not the underlying fact that this
  technique type has no private, solo-completable artifact. Facilitator
  sign-off should feed into `DevelopmentEvidence` as the witness record
  once that mechanism is wired up — pilot it manually (a real scheduled
  call, a real facilitator, a written sign-off) before any new platform
  code exists for it.

## USING THESE TEMPLATES GOING FORWARD

1. Determine craft-based vs. relationship-based per the test above.
2. Fill in the [REAL TOOL] field FIRST, before writing lesson content — if it can't be filled honestly, stop and flag the gap rather than writing around it.
3. If adapting structure from an open-licensed source (OpenStax Marketing CC BY 4.0, MIT OCW, etc.), cite it in the [REAL TOOL] field per its actual license terms — never adopt NC-licensed text into anything that could touch Cyberstore/paid tiers without checking that conflict first.
4. One lesson + one workbook per tier (Explorer/Builder/Innovator/Leader) = 8 documents per curator, ideally, though Explorer-tier alone is a reasonable unit of shippable progress. A single combined lesson-and-workbook file is also acceptable per tier where that reads better (Cooke's Explorer tier, Dodd's Builder tier) — match whichever shape the content actually needs, don't force a split for its own sake.
5. Scope reminder: 26 curators × 4 tiers × 2 documents = 208 documents at full build-out. Plan accordingly — this is a large body of work, not a quick fill-in exercise.
6. **Tier differentiation for relationship-based (Template B) curators, added 22 Aug 2026 after Dodd's Builder-tier build:** Explorer tier trains raw observation (watch/listen, name what you notice). Each tier beyond Explorer should add something Explorer didn't have — not just "the same observation, done more times." Dodd's Builder tier's answer was a *framework*: six real, historically-grounded case studies the learner analyses for a pattern (Part One) before applying that trained pattern-recognition to a real coaching attempt (Part Two). Apply the same principle going forward for every relationship-based curator: identify what genuinely new layer each tier adds — a framework, a harder judgment call, a longer time horizon — rather than defaulting to "more sessions, same task" as the only way to raise the bar.
